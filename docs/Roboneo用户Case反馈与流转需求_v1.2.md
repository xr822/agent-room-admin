# Roboneo 用户 Case 反馈与流转需求

> 范围：仅「反馈」及与之复用的「提缺陷」能力  
> 适用端：Roboneo 后台 · Room 详情  
> 版本：v1.2（反馈专题）

---

## 1. 一句话定义

在 Roboneo Room 中建立统一用户 Case 反馈入口：支持将「输入输出任务」与「服务端执行任务」作为平级内容独立或组合选择，完成问题分类后，可一次流转至群聊、缺陷系统和需求优化表。

另在服务端执行流程的 Error 旁提供快捷「提缺陷」入口，复用同一套提缺陷规则。

---

## 2. 背景与目标

### 2.1 背景

产品侧通过后台走查真实用户 Case，发现生成效果、Agent 响应、产品体验及用户需求等问题时，需人工整理上下文再分别同步到群、提缺陷或记需求表，重复成本高。

一期仅在 **Roboneo 后台**建设统一反馈入口；**不替代**服务端执行步骤已有的「提 Bug」能力，本需求解决的是 **Case 层**反馈、流转与沉淀。执行流 Error 快捷提缺陷与反馈流程共用规则，便于从明确异常直接建单。

### 2.2 目标

1. 选择一条或多条与本次 Case 相关的后台内容；  
2. 对 Case 进行问题分类并补充问题描述；  
3. 一次提交后按需流转到：上报到群 / 提缺陷 / 同步需求优化表；  
4. 自动带出后台已有信息（含图片、视频），减少复制、截图和手填；  
5. 在服务端执行 Error 旁可一键提缺陷。

---

## 3. 范围

### 3.1 包含

- Room 详情新增「反馈」入口  
- 选择反馈内容（输入输出任务、服务端执行任务）  
- 反馈类型与问题描述  
- 三种处理方式多选：上报到群、提缺陷、同步需求优化表  
- 提交结果分项展示与失败重试  
- **服务端执行流程 Error 旁「提缺陷」入口**（复用提缺陷规则）

### 3.2 不包含

- Virash 后台同等能力  
- 用户场景 / 优质 Case 单独沉淀  
- 自动判断问题类型、自动提炼正式产品需求  
- 删除或替换原有「提 Bug」能力（可并存）

---

## 4. 反馈可选内容

| 反馈内容 | 定义 | 选择规则 |
|---|---|---|
| **输入输出任务** | 一轮用户输入 + 对应 Agent 输出 | 绑定为一个整体，不拆开单选 |
| **服务端执行任务** | 一段完整服务端执行流程 | 独立选择，不随输入输出自动勾选 |

规则：至少选 1 条；可组合；文本与媒体（含 Agent 输出图/视频）自动带出。

---

## 5. 反馈交互流程

```text
点击「反馈」
  → Step1 选内容（≥1）
  → Step2 反馈类型* + 问题描述*
  → Step3 处理方式*（默认勾选「上报到群」，可取消）
  → 提交（各目标独立执行）
  → Step4 结果与重试
```

---

## 6. 反馈类型

| 类型 | 说明 |
|---|---|
| 生成效果 | 任务正常产出，但人物/动作/风格/画质/参考遵循等不符合预期 |
| Agent 响应 | 理解、回复、上下文承接或行为选择不符合预期 |
| 产品体验 | 用户在理解或使用过程中明显受阻 |
| 需求优化 | 当前能力未覆盖或值得增强的产品需求/优化点 |
| 其他 | 暂时无法归入以上类型 |

选「需求优化」时自动勾选「同步需求优化表」。

---

## 7. 处理方式

- 上报到群、提缺陷、同步需求优化表；至少 1 项，可多选  
- **默认勾选「上报到群」，可取消**

---

## 8. 提缺陷规则（反馈内与执行流入口共用）

勾选「提缺陷」或点击执行流 Error 旁「提缺陷」后，展开/弹出缺陷表单。

### 8.1 字段一览

| 字段 | 规则 | 是否可编辑 |
|---|---|---|
| 经办人 | **必填**；支持按姓名/邮箱/工号搜索 | 是 |
| 缺陷名称 | **【Agent Bug】**（固定）+ **失败原因**（自动填充，可编辑） | 是 |
| Bug 平台 | 默认 **Web** | 否 |
| Bug 发现阶段 | 默认 **上线遗漏** | 否 |
| Bug 如何发现 | 默认 **无** | 否 |
| Bug 类型 | 默认 **需求缺陷** | 否 |
| 优先级 | 人工选择：高 / 中 / 低 / 极低 | 是 |
| 严重程度 | 人工选择：严重 / 重要 / 一般 / 次要 / 微小 | 是 |
| 出现概率 | 人工选择：必现 / 中高概率 / 低概率 / 单次 | 是 |
| 重现步骤 | 基于所选 Case / Error 上下文自动拼装 | 是 |
| 备注 | **可选**；复用原「提 Bug」备注规则，自动带出 room/task/step/error 等上下文 | 是 |

### 8.2 服务端执行流入口

- 位置：与步骤操作链并列，如 `详情` / `AIGC(任务)` / `AIGC(子)` / **`提缺陷`**
- 有 Error 的步骤才展示「提缺陷」
- 缺陷名称自动填充：`【Agent Bug】` + 失败原因（取自 Error 文案中的失败原因）
- 经办人必填；备注按原提 Bug 备注规则预填，可改

示例：

```text
错误框：code:501 | type:mcp_call_fail 失败原因：请求 mcp server 超时，连接断开
缺陷名称：【Agent Bug】请求 mcp server 超时，连接断开
操作行：详情 · AIGC(任务) · AIGC(子) · 提缺陷
```

---

## 9. 校验与提交结果

| 项 | 规则 |
|---|---|
| 反馈内容 | ≥ 1 条（反馈流程） |
| 反馈类型 / 问题描述 | 反馈流程必填 |
| 处理方式 | ≥ 1；默认含上报到群 |
| 提缺陷 | 经办人、缺陷名称、优先级、严重程度、出现概率、重现步骤必填 |

各流转目标独立执行；失败可重试。

---

## 10. 验收标准

1. Room 详情可进入反馈流程  
2. 输入输出绑定选择；媒体（含 Agent 输出）可展示  
3. 服务端执行任务可独立选择；两类可组合  
4. 处理方式默认勾选上报到群且可取消  
5. 提缺陷字段符合 §8.1（含固定值不可编辑）  
6. **执行流 Error 旁有「提缺陷」，经办人必填，备注可选且按原规则预填**  
7. 一次提交可同时完成所选流转；失败可重试

## 13. 上报到群 · 精准定位（v1.3）

### 13.1 现状问题

当前群卡片偏摘要，常见缺口：

1. **问题描述过短/无信息量**（如仅填「1」），群内无法理解现象；  
2. **执行记录只写「N 步，去房间看」**，不展示失败步骤、error code / type、失败原因；  
3. **缺少深链**：只能进 Room，不能直达某条 task / 失败步骤；  
4. Agent 输出 / 关键媒体未在卡片中体现，效果类问题更难对齐。

### 13.2 目标

群消息打开后，**不进后台也能判断**：是哪次输入、哪条执行、哪一步、什么失败原因；进后台后能 **一键落到对应 task**。

### 13.3 卡片必含信息

| 区块 | 内容 | 说明 |
|---|---|---|
| 标题 | `Case 反馈 · {反馈类型}` | 与现网一致 |
| 基础定位 | UID、Room ID、应用/客户端、Room 链接 | 自动 |
| 问题描述 | 走查填写的完整描述 | **建议前端限制最少 10 字**，避免无意义提交 |
| 输入输出（每条） | task_id、用户输入摘要、Agent 输出摘要、媒体数量 | 文本可截断，完整内容靠深链 |
| 执行记录（每条） | task_id、总步数、状态；**失败步骤列表**：步骤名 + code/type + **失败原因** | 无 Error 时标明「无明确 Error」 |
| 操作按钮 | **查看房间详情**；**定位到任务**（带 `task_id` 查询参数）；若有失败步骤可再提供 **定位到失败步骤** | 深链需后台详情页支持 |

### 13.4 推荐卡片结构示例

```text
Case 反馈 · Agent 响应

UID：3026656079
Room ID：…
应用 / 客户端：Virash · web
房间链接：https://…/room/…

问题描述：
用户要求继续改上一轮结果，但 Agent 未承接上下文，且 AIGC 步骤超时失败。

已选内容 · 2 项

【输入输出 1】task_id=5E2566D2…
用户输入：请根据耳机产品图生成…（截断）
Agent 输出：好的，我将…（截断）
媒体：输入 2 · 输出 1
定位：…/room/…?task_id=5E2566D2…

【执行记录 1】task_id=5E2566D2…（11 步 · failed）
失败步骤：
- 9. (657)AIGC工具调用 · code:501 | type:mcp_call_fail · 失败原因：请求 mcp server 超时，连接断开
定位：…/room/…?task_id=5E2566D2…&tab=execution

[查看房间详情]  [定位到任务]
```

### 13.5 产品规则补充

1. 问题描述：必填，**不少于 10 个字**（可配置）；提交前若过短给提示。  
2. 选中执行任务时：群消息**必须展开失败步骤摘要**，禁止仅写「完整记录请前往房间详情」。  
3. 选中输入输出时：至少带出用户输入摘要；有 Agent 输出/媒体时一并摘要。  
4. 深链参数建议：`task_id`、可选 `step_index` / `error=1`；Room 详情打开后自动滚动并高亮。  
5. 飞书卡片若有字数/图片限制：正文保留定位关键字段，长文本与媒体用「查看详情」承载。

### 13.6 验收补充

1. 群消息可见失败步骤的 code/type/失败原因（有 Error 时）  
2. 群消息含可点击的任务级深链（不仅是 Room 首页）  
3. 问题描述过短时不可提交（或强提示后仍允许，需产品二选一；**默认建议拦截**）
